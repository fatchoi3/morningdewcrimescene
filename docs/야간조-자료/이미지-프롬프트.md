# 「야간조」 단서 사진 — 생성 프롬프트

> 카드 109장 중 **실사 사진이 필요한 것은 63장**. 나머지는 폰·태블릿 화면 UI, 카메라 통행 기록 HTML, 평면도 SVG 다.
> 저장 위치는 `public/images/yaganjo/` 이고 **파일명은 데이터팩(`src/data/yaganjo/`)의 `image` 값 그대로**다.
>
> **진행 — 34 / 63 완료** (2026-09-24 에 19장 추가). D3 여권과 P1 여권 보관함은 안전 필터로
> **뽑지 않기로 했다**(§5-ⓑ). **남은 것은 32장** — 종이·소품 13장과 현장 19장이다.
> 이 문서의 프롬프트는 전부 **실제로 보낸 마지막 판본**이다. 재시도로 고친 여덟 장도 반영돼 있다.

> 2026-09-17, Gemini(Flash)에서 아홉 장을 실제로 뽑아 얻은 것이다. 열네 번 생성해서 아홉 장을 건졌고,
> 초반 다섯 장에 아홉 번을 쓴 뒤 처방이 서고 나서는 네 장에 네 번으로 떨어졌다.
> **이 문서의 규칙은 추측이 아니라 실패 다섯 건에서 나온 것이다.**

## 0. 한 줄 요약

**「글자를 없애라」가 아니라 「한글로 채우되 초점을 빗나가게」다.**

## 1. 실패 다섯 — 무엇이 안 되는지부터

| | 무엇을 시켰나 | 무슨 일이 났나 |
|---|---|---|
| **1** | 「**경찰** 감식 증거 사진」 | 「경찰」이 **피사체로 옮아갔다.** 물류센터 순찰 일지가 「경찰 파트롤 로그」가 됐다 |
| **2** | 「글자는 초점 밖으로 흐리게」 | 약했다. 제목이 또렷하게 찍히고 **한글이 깨졌다** |
| **3** | 「인쇄된 제목·로고·영문이 하나도 없는 **빈 양식지**」 | 손글씨와 서명까지 같이 지워졌다. 표가 통째로 비어 「결재란 첫 칸에만 서명」이라는 급소가 사라졌다. **그런데 영문 라벨은 그대로 들어왔다** |
| **4** | 「**영어나 로마자는 단 한 글자도** 안 된다」 | **키릴 문자로 갔다.** 러시아어 공문이 나왔다. 양식 서류엔 뭔가 적혀 있어야 한다고 모델이 강하게 믿어서, 금지하면 금지 안 된 문자를 찾아간다 |
| **5** | 「위쪽에 굵은 **제목 한 줄**이 있고 가운데 **항목 칸**만 파란 볼펜 손글씨로」 | **그 설명문이 종이에 그대로 인쇄됐다.** 종이에 「굵은 제목 한 줄, 인쇄 양식 서류」·「파란 볼펜 손글씨」가 찍혀 나왔다 |

**그래서 셋을 지킨다 — ① 「경찰」을 쓰지 않는다 ② 구조를 설명하지 않고 문서 이름을 준다 ③ 글자를 빼지 말고 한글로 채우되 초점을 빗나가게 한다.**

## 2. 톤 두 갈래 — 베이스

**⒜ 증거 촬영대** (사물함 · 소지품 · 현장 물증 · 서류)
```
증거 촬영대에서 찍은 감식 사진: 짙은 회색 무광 촬영대 위에 <피사체> ; 비스듬히 내려찍기, 단일 하드 스포트라이트, 깊은 그림자, 옆에 숫자 증거 표식 하나 ; 사람 없음 ; 실사 사진, 일러스트·CG 금지
```
서류는 「비스듬히」 대신 **「정면에서 살짝 기울여 내려찍기」**.
비율은 프롬프트에 쓰지 않고 버튼으로 **1:1** 을 고른다(§6-ⓑ).

**⒝ 현장** (통로 · 휴게실 · 충전소 · 탈의실 같은 공간)
```
<공간>을 찍은 감식 사진: 천장 형광등 백색광 아래 회색 콘크리트 바닥, 정면에서 한 걸음 물러나 찍기 ; <피사체> ; 사람 없음 ; 실사 사진, 일러스트·CG 금지
```
비율은 프롬프트에 쓰지 않고 버튼으로 **16:9** 를 고른다(§6-ⓑ). 프롬프트에 적으면 그 글자가
소품 위에 인쇄돼 나온다(§1-5).

## 3. 글자 꼬리 — 종이·라벨이 나오는 모든 장에 반드시 붙인다

```
; 종이 위의 문자는 한글 뿐이고 영어나 로마자는 없으며 카메라 초점이 종이 면에서 크게 빗나가 있어 어느 낱말도 판독되지 않는다
```

**서명이 있는 장에는 한 줄 더:**
```
; 서명은 이름이 아니라 흘려 쓴 획으로만 보인다
```
→ 서명 이름이 읽히면 안 된다. 실제로 「지우영」·「신주영」이 또렷하게 찍혀 나온 적이 있고, 그 각서는 차민우와 박태식 것이라 다른 이름이 보이면 판이 헷갈린다.

**얼굴이 들어갈 수 있는 장(사원증·학생증·신분증):**
```
; 사진 자리는 스포트라이트 반사로 하얗게 날아가 아무것도 보이지 않는다 ; 사람 없음, 얼굴 없음
```

## 4. 문서 이름을 직접 준다 — 구조를 설명하지 않는다

「위쪽에 굵은 제목 한 줄이 있고 가운데 항목 칸만…」이라고 쓰면 **그 말이 종이에 인쇄된다.**
대신 **한국 서류의 실제 이름**을 준다 — 「합의 각서」 · 「사고 조사 보고서」 · 「야간 순찰 점검표」 · 「복약 안내문」 · 「시험 시간표」 · 「심야조 명부」 …
그러면 그 이름이 제목으로 또렷하게 찍히고 나머지는 흐려진다. **그게 맞는 그림이다** — 카드 앞면이 이미 값을 들고 있으므로 사진은 「무슨 서류인지」만 말하면 된다.

## 5. 안전 필터 — 두 번 거부당했다

### ⓐ 아이 사진

A4에서 **「미성년자를 그런 식으로 묘사하는 이미지는 생성할 수 없습니다」**로 거부당했다. 원인은 「담요에 싸인 아기 사진」이다.

**우회 둘:**
- **소품을 바꾼다** — 아기 사진 대신 아주 작은 면양말 한 켤레. 뜻은 그대로 서고 필터에 안 걸린다
- **뒷면만 찍는다** — 「인화지 뒷면이 위로 오게 뒤집혀 있고 뒷면에 볼펜으로 날짜가 적혀 있다」.
  야간조에서는 이쪽이 **오히려 설정에 맞다** — D4·X4는 「사진 뒷면의 생년월일」이 폰 잠금의 출처이므로 뒷면이 요점이다

→ **아이·아기·딸 사진이 들어가는 장은 전부 「뒷면만」으로 바꾼다.**

### ⓑ 여권 — 우회하지 않는다

D3 에서 거부당했다. **「여권이나 신분증 같은 정부 발급 신분 문서는 생성할 수 없습니다」.**
사원증(A5)과 학생증(B4)은 통과했다 — 회사·학교가 발급한 것은 걸리지 않고 **국가가 발급한 것만** 막힌다.

낱말을 바꿔 통과시키는 길이 없지는 않지만 그렇게 하지 않는다. **D3 여권과 P1 여권 보관함은 사진 없이 둔다.**
두 장 다 카드 앞면의 글이 이미 제 몫을 한다 — D3 는 「초록 표지」, P1 은 「칸 셋 중 가운데만 비어 있다」가 요점이고,
그것은 사진이 아니라 문장이 말하는 편이 낫다.

## 6. 조작 수칙 — **2026-09-24 에 전부 다시 썼다**

> 9월 17일과 화면이 달라졌다. 그때 쓰던 방식은 이제 **그림을 안 그린다.**

### ⓐ 채팅방이 아니라 「이미지 만들기」로 간다 — **이게 제일 크다**

일반 채팅방(`/app`)에 서술문을 넣으면 **그림 대신 「이미지 생성용 최종 영어 프롬프트」를 써 주고,
참고 사진이랍시고 스톡 이미지(Envato)를 한 장 붙인다.** 실기에서 첫 시도가 그렇게 날아갔다.

**`https://gemini.google.com/images` — 「이미지 만들기」로 들어간다.** 모델은 **Nano Banana 2**다.
여기서는 같은 서술문이 그대로 사진이 된다.

### ⓑ 비율은 프롬프트가 아니라 **컨트롤**로 준다

입력창 아래 **「가로세로 비율」** 버튼이 있다(1:1 · 9:16 · 3:4 · 4:3 · 16:9).
그래서 **프롬프트 꼬리의 「1:1 정사각」·「16:9 가로」는 지웠다** — 그 글자가 종이에 인쇄돼 나오는 것이
바로 §1-5 다. **앞으로 보낼 프롬프트에는 비율을 쓰지 않는다 — 버튼으로 고르고 쏜다.**
§2 의 베이스 둘에서도 꼬리를 걷어냈다. 이미 뽑은 장(✅)과 뽑지 않기로 한 D3·P1 에 옛 꼬리가 남아 있는 것은
**실제로 보낸 판본을 그대로 둔다**는 이 문서의 원칙 때문이지, 다시 그렇게 쓰라는 뜻이 아니다.

### ⓒ 붙여넣기는 `execCommand('insertText')`로

입력창은 Angular `rich-textarea` 다. 자동화로 한 글자씩 타이핑하면 **한글 사이 공백과 세미콜론이 통째로
사라진다**(364자가 242자로 줄어든 적이 있다). 마우스로 칸을 찍고 타이핑하면 첫 한 번은 되는데
두 번째부터 또 먹는다. **선택 → `document.execCommand('insertText', false, 텍스트)`** 가 유일하게 안정적이다.
넣은 뒤 **글자 수를 반드시 세어 본다.**

### ⓓ 보내기 버튼은 **글자를 넣은 직후에는 없다**

`aria-label="메시지 보내기"` 버튼은 입력이 반영된 뒤에 그려진다. 넣자마자 찾으면 `null` 이다.
**0.3초 간격으로 스무 번쯤 다시 찾는다.** 그리고 생성 중에는 그 자리가 **중지 버튼**이라,
다음 장을 쏘기 전에 **중지 버튼이 사라질 때까지 기다린다** — 안 기다리면 그 장은 통째로 날아간다.

### ⓔ 크롬이 두 번째 다운로드부터 막는다

첫 장은 내려오고 그 뒤로 조용히 전부 차단된다. 자동이든 진짜 클릭이든 똑같다.
**주소창의 차단 아이콘 → 「gemini.google.com이 여러 파일을 다운로드하도록 항상 허용」**을 한 번 켜 둔다.
(자물쇠 → 사이트 설정 → 자동 다운로드 → 허용도 같다.) 이건 사람이 눌러야 한다.

### ⓕ 이름이 겹치면 크롬이 `(1)`을 붙여 짝이 꼬인다

한 방을 다 뽑고 **`방이름-1.png … -N.png` 로 순서대로 통째로 내린 다음**, 눈으로 보고 이름을 짝짓는다.
장마다 이름을 주고 받으면 실패·재시도가 섞이면서 어느 파일이 어느 카드인지 어긋난다.

### ⓗ 새 방의 **첫 한 장**은 JS 클릭이 안 먹는다

「이미지 만들기」 랜딩 화면의 ↑ 버튼은 `button.click()` 으로도, 합성 포인터 이벤트로도 전송되지 않는다.
**진짜 마우스 클릭으로 눌러야 한다.** 좌표는 DOM 에서 읽어 쓴다 —
`아이콘의 getBoundingClientRect()` 중심 × `1568/innerWidth`. 한 번에 안 들어가면 **같은 자리를 한 번 더** 누른다
(첫 번째가 호버로 먹히는 일이 잦다). **방에 들어간 뒤로는 JS 클릭이 정상 작동한다.**

### ⓘ 방이 길어지면 **지시문이 소품에 인쇄된다**

§1-5 가 한 장짜리 사고였다면 이건 누적 사고다. 한 방에서 같은 꼴의 프롬프트를 예닐곱 장 보내고 나면,
모델이 **설명 절 자체를 내용으로 그리기 시작한다.** 실기에서 수첩 사진에
「잉크가 얕게 흘러간 자국만 보임」·「한 글자도 색별 가능」이 **본문 손글씨로 적혀 나왔고**,
충전기 패널에는 금지해 둔 영문 `POWER / ACTIVE / FULL` 이 붙어 나왔다.

**막는 법 둘.**
- **한 방은 다섯 장까지.** 여섯째부터 눈에 띄게 샌다
- **긴 설명 절을 짧게 자른다.** 「카메라 초점이 종이 면에서 크게 빗나가 있어 어느 낱말도 판독되지 않는다」처럼
  긴 문장이 통째로 인쇄된다. **「글자는 초점 밖이라 읽히지 않는다」** 정도로 줄이면 안 새고 효과는 같다

### ⓙ 증거 표식 색을 **프롬프트에 박는다**

그냥 「숫자 증거 표식 하나」로 두면 방마다 노랑·검정이 갈린다. 앞의 아홉 장이 전부 노란 표식이라
**「옆에 노란 플라스틱 숫자 증거 표식 하나」**로 못박았다. 박은 뒤로는 한 장도 안 틀어졌다.

### ⓚ 하루 한도가 있다 — 그리고 **말없이 막힌다**

한 계정으로 이어 뽑다 보면 어느 순간 ↑ 를 눌러도 **아무 일도 일어나지 않는다.**
오류 문구도, 한도 안내도 없고, **네트워크 요청 자체가 안 나간다**(개발자 도구로 확인했다).
새 탭·새 방·새로고침 다 소용없다. 2026-09-24 에 **한 세션에 33장쯤에서** 걸렸다.
**이때는 고칠 것이 없다. 다음 날 이어서 뽑는다.**

### ⓖ 그대로인 것

1. **프롬프트는 한 줄.** 개행이 들어가면 문단마다 전송돼 쪼개진다. 구분은 세미콜론과 하이픈
2. **갈래를 섞지 않는다.** ⒜와 ⒝를 섞으면 3~4장째부터 배경이 옮아간다.
   장수는 **§6-ⓘ 를 따른다** — 여기 적혀 있던 「한 방에 6~8장」은 2026-09-24 실기로 갈아 끼운 옛 값이다.
   그리고 **방은 예고 없이 죽는다** — 빈 응답이 연달아 나오고 중지 버튼이 걸린 채 안 풀리면 새 방으로 옮긴다
3. **재시도 기준 넷** — 얼굴이 들어왔다 / 한글이 깨져서 또렷하다 / 일러스트 느낌이 난다 /
   **카드의 급소가 화면에 없다**(가장 흔하다. 첫 E1 이 제목만 또렷하고 정작 「신청 이력 표」가 안 보였다)
4. 받은 파일은 `public/images/yaganjo/`에 **데이터팩의 `image` 값 그대로**(ASCII 케밥) 저장.
   1:1은 1024×1024, 16:9는 1600×900, jpeg 품질 80
